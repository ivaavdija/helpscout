Field 4 — Specific Topic  Conditional on Category
A short list of the most common specifics for each category, plus Other always available.

Example — Request + Refund: Charged after I cancelled · Duplicate charge · Event cancelled · Couldn't watch (geo block) · Bought wrong plan · Other
Field 5 — Free Text  Always visible · Optional
Open text — always shown. Placeholder changes based on type: "Describe what happened…" for issues, "Tell us what you'd like to request…" for requests, etc.

Part 4 — End-to-end process map

Full ticket lifecycle — who does what, when, and why

Six stages from submission to close. Each row shows the actor, action, and any conditions that change the path.
🙋 Customer
S0
Submits via Beacon contact form
Fills: Account email (optional) → Type (required) → Category → Specific topic → Free text. Submits message.
IF free text empty → ticket still creates IF account email filled → pre-populates field on ticket
⚙️ System
S0
Ticket created in Help Scout
Beacon data maps to custom fields: Type → Ticket Type field, Category → Issue Category field, Topic → Beacon Topic field (read-only). Auto-reply sent to customer.
IF Type = Complaint → add tag: priority review IF Category = Streaming → auto-set Live Event = ? (agent confirms)
🎧 Agent
S1
Opens ticket — first 30 seconds
Confirms Issue Category (pre-filled from Beacon — correct or update). Sets Account Match. These 2 fields are required before any reply.
IF Account Match = Matched → proceed to Stage 2 IF Account Match = Wrong email → send wrong-email reply → set Pending → wait for customer response → update Account Match → proceed to Stage 2 IF Account Match = No account → send no-account reply → set Pending → if no response in 5 days → auto-close (Resolution = No response) IF Account Match = Multiple accounts → send disambiguation reply → set Pending
🎧 Agent
S2
Handle the ticket
Fill optional fields as facts become known. Add 0–2 symptom tags if specific symptom confirmed. Respond to customer.
IF Category = Streaming AND Live Event Related = Yes → check if multiple reports → if yes, add tag: known incident + live urgent → set Severity = Critical → alert team IF Category = Payment/Refund AND Ticket Type = Request → fill Refund Reason field IF Category = Subscription AND Ticket Type = Request AND Topic = Cancellation → process cancellation → update Resolution on close IF Subscription Type = In-app iOS/Android → refund goes through Apple/Google, not us → advise customer accordingly
🔺 Escalation
S3
Escalation path (when needed)
Some tickets require another team. Agent fills Escalation Link and sets ticket to Pending.
IF tag = venue signal → escalate to production team (not standard support) → paste Slack link in Escalation Link field → set Pending IF tag = fraud → internal investigation workflow → add tag: internal → do NOT reply to customer → escalate to security IF Refund Reason = Geo restriction → escalate to rights team for approval before refunding IF tag = vip → notify manager → prioritize above normal queue → response within 30 mins IF escalation resolved → update Escalation Link → reopen ticket → complete resolution → close
🎧 Agent
S4
Close the ticket
Fill Resolution field (required at close). Set Status = Closed. Ticket complete.
IF Resolution is blank when agent tries to close → workflow prompts agent to fill before closing IF Resolution = Refunded → record amount in notes (for finance audit) IF Resolution = Escalated → do NOT close → keep Pending until external team resolves IF tag = proactive followup → set follow-up reminder before closing
⚙️ System
S5
Automated rules (run continuously)
Help Scout workflows handle repetitive state changes without agent input.
IF Status = Pending AND no reply for 5 days → auto-close → Resolution = No response IF tag = live urgent added → set Severity = Critical → notify team channel IF Status = Closed AND Resolution = blank → reopen + alert agent IF Category = Payment/Refund AND tag = duplicate charge → auto-route to billing queue
