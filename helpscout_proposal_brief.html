The problem

Our current tag system is broken

Over time, tags have been used to carry too many different kinds of information. The result is 170 tags that agents use inconsistently, reports that can't be trusted, and customers waiting longer than they should.

📧
Wrong email contacts
No field to capture this. Every case needs an extra reply just to find the account — adding delay on every affected ticket.
🏷️
170 messy tags
Agents hunt through duplicates and near-synonyms. "billing issue", "issue: billing", "payment failed" all exist. No consistency.
📊
Reporting is unreliable
Refund approval rate, device breakdown, subscription type churn — all impossible to measure accurately with the current system.
💳
No refund audit trail
Refund reason and outcome are not structured anywhere. We can't track why refunds were requested or what percentage were approved.

How a ticket works

Ticket lifecycle — 4 steps

Two required actions (Category + Account Match), the rest are optional and filled only when relevant.

1

Ticket arrives

  • Beacon: account email already captured if customer filled it
  • All fields blank — agent fills on first review
  • Status: Open
→
2

First 30 seconds

  • Category — what is this about?
  • Account Match — can we find their account?
  • If wrong email: send request, set Pending
→
3

During handling

  • Device, Subscription Type — only if stated
  • Live Event Related — if a live broadcast
  • Add 0–2 symptom tags if specific
  • Escalation Link if routed to another team
→
4

At close

  • Resolution — what actually happened
  • Refund Reason if a refund was involved
  • Status: Closed

Implementation — 4 phases, 6–8 weeks

Rollout plan

Each phase is self-contained. No platform downtime. Phases 1 and 2 are fully reversible.

Phase 1
Configure
Week 1
  • Create B2C custom fields in HS settings
  • Create B2B fields in partner inboxes
  • Add account email field to Beacon form
  • Draft wrong-email saved replies
  • Prepare agent quick reference card
Phase 2
Soft Launch
Weeks 2–3
  • 30-min team briefing
  • Agents start filling Category + Account Match on new tickets
  • Resolution introduced at close
  • Old tags still available — parallel running
  • Monitor fill rates
Phase 3
Tag Migration
Weeks 4–5
  • Stop using compound tags
  • Send migration CSV to Help Scout support
  • HS renames / merges / deletes old tags
  • Verify via Tags report spot check
  • Final 22-tag set active
Phase 4
Automate
Weeks 6–8
  • Build saved queue views per category
  • Auto-close no-response tickets (5 days)
  • Prompt if Resolution blank at close
  • Live event alert workflow
  • First reporting dashboard review
