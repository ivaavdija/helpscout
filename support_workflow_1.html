The Customer Beacon Flow

What the customer sees and selects. Their answers automatically map to internal Custom Fields and Tags — no agent input needed at intake.

Who: Customer
When: Ticket creation
1
Identification
Two fields collect identity before the customer describes their issue. One is required by Help Scout (contact email), one is ours.
📧
Contact Email
Standard Help Scout Beacon field. This is the email the customer writes from.
Example: "anna.svensson@gmail.com"
Required
🔑
Account Email
Prompt shown to customer: "Which email address is your subscription linked to? Leave blank if it's the same as above."
Maps to: Account Email custom field on ticket. If different from contact email, system auto-adds an internal note alerting the agent.
Example: "anna.svensson@work.com" — different from Gmail address above
Optional
💡
Why this field matters: A significant portion of B2C tickets arrive from an email not linked to the customer's account. Without this field, agents send a manual reply to ask — adding one full back-and-forth to every affected ticket. This one field can eliminate that delay entirely when customers fill it in.

Auto-Reply & Deflection Rules — Zero-Touch Resolution
Some tickets can be resolved or deflected before an agent reads them. These workflows fire the moment the ticket is created.
Deflection & Auto-Close Rules
IF Customer selects "I forgot my password"
Auto-reply: Password reset instructions + direct link to reset page + "Check your spam folder" tip
Set Status = Closed — zero-touch resolution. If customer still can't reset, they reply and ticket reopens.
⚙️ System
IF Customer selects "I want to cancel my subscription"
Auto-reply: Self-serve cancellation guide (how to cancel via account settings) + link
Set Status = Pending — if customer can self-serve, ticket auto-closes after 5 days. If they can't, they reply and agent handles.
⚙️ System
IF Customer selected "App or Device Issue" AND specific topic = "Can't cast to TV"
Auto-reply: Casting troubleshoot guide (device-agnostic steps for Chromecast, AirPlay, Smart TV)
Set Status = Pending — most casting issues resolve with the guide. Agent reviews if customer replies.
⚙️ System
IF Status = Pending AND no customer reply for 5 days
Send closing notice: "We're closing this ticket as we haven't heard back — reply any time to reopen."
Set Resolution = No response — closed. Set Status = Closed.
⚙️ System
📊
Deflection rate tracking: Run a monthly report on tickets where Status was set to Closed automatically (password reset + cancellation guide deflections). This measures self-serve success rate and helps identify whether guides need improving.

The Agent Workflow

Because Phases 1 and 2 did the heavy lifting, the agent's job is to verify, enrich, act, and close — not classify from scratch. Most tickets need just 2–3 agent actions beyond the reply.

Who: Support Agent
When: Ticket handling
1
Triage — First 30 Seconds
Two mandatory field checks before any reply. These are the only two fields that are always required.
✅
Verify Issue Category (pre-filled from Beacon)
Confirm the Beacon-mapped category is correct. Most of the time it is. Update only if the customer's free text reveals a different actual topic. Example: customer selected "Streaming" but free text reveals they can't log in at all → update to "Account / Access".
Required
🔍
Set Account Match Status
Look up the customer in the subscription/admin system using their contact email. If they provided an Account Email in the Beacon form, use that. Set one of the five values below.
Matched — Direct Matched — Via Account Email Wrong Email Used No Account Found Multiple Accounts
Required
⚠️
Account Match determines the path: See the full Account Match decision tree in Step 2 below before replying.
2
Account Match Decision Tree
Every possible Account Match outcome and the exact action to take.
Account Match → Agent Action
MATCHED — DIRECTContact email matches account email
Proceed directly to troubleshooting. No identity steps needed.
🎧 Agent
MATCHED — VIA ACCOUNT EMAILCustomer provided different account email in Beacon
Account found via Beacon account email field. Proceed to troubleshooting. Note the email discrepancy in the ticket for any account changes.
🎧 Agent
WRONG EMAIL USEDContact email not found — may have different account email
Send wrong-email reply: "We couldn't find an account linked to [contact email]. Could you confirm the email you used when signing up?"
Set Status = Pending.
When customer replies with correct email → look up account → update Account Match to Matched → proceed.
🎧 Agent
NO ACCOUNT FOUNDNo subscription exists for any provided email
Send no-account reply: "We couldn't find an active subscription for any of the emails you've provided. Have you subscribed directly or via the Apple/Google app store?"
Set Status = Pending.
IF no reply in 5 days → System auto-closes. Resolution = No response — closed.
IF they confirm an in-app purchase → update Subscription Type = In-app iOS/Android and advise accordingly.
🎧 Agent
MULTIPLE ACCOUNTSMore than one account found for this customer
Send disambiguation reply: "We found multiple accounts linked to your details. Could you confirm which email address you normally use to log in?"
Set Status = Pending. Do not act on any account until the correct one is confirmed.
🎧 Agent
3
Core Handling — Category-Specific Workflows
Once account is confirmed, agent handles based on category. Fill optional fields only when confirmed — never guess.
IF Category = Payment / Refund
Ticket Type = Request + refund
Fill Refund Reason. Check eligibility against refund policy before confirming. Get manager approval if Reason = Geo restriction. Log reason even if declined.
🎧 Agent
Payment Source = In-app iOS or Android
We cannot process this refund. Advise customer to contact Apple (Settings → [Name] → Subscriptions) or Google Play (Play Store → Subscriptions). We have no access to these transactions.
🎧 Agent
Tag = duplicate charge
Verify in Stripe before any action. Check for: two separate charges, one failed + one successful, or recurring charge misunderstood. Only refund confirmed duplicates.
🎧 Agent
Refund Reason = Geo restriction
Escalate to rights team for approval. Do not refund without sign-off. Paste rights team Slack link in Escalation Link field. Set Pending.
🔺 Escalation
IF Category = Streaming
Single report + specific symptom
Standard troubleshoot: 1) Clear cache / refresh, 2) Try different browser/device, 3) Check internet speed, 4) Reinstall app. Add symptom tag (black screen / no audio / buffering). Fill Device field.
🎧 Agent
Multiple reports, same symptom, same time window
Add tag: known incident + live urgent. Set Severity = Critical. Send standard holding reply. Alert production team in Slack. Paste Slack link in Escalation Link. Set all related tickets to Pending.
🎧 Agent + 🔺 Team
Tag = venue signal
This is a production-side issue, not a user-side one. Do NOT send troubleshooting steps — they won't help. Escalate to production team immediately. Set Pending. Send: "We're aware of a signal issue and our production team is working to fix it."
🔺 Escalation
Customer using VPN → geo block
Advise: VPN detected by platform, must disable VPN to watch. This is platform policy. Not eligible for refund if VPN was the cause.
🎧 Agent
IF Category = Subscription
Ticket Type = Request + cancellation
Fill Subscription Type. Check cancellation date — some plans cancel at period end, not immediately. Confirm in writing: cancellation date + when access ends. If customer also wants refund, that's a separate refund request evaluation.
🎧 Agent
Renewal issue / charged unexpectedly
Check if auto-renewal was enabled (it is by default). Verify what the customer was notified of when subscribing. If within grace period and legitimate confusion, approve goodwill refund. Fill Refund Reason = Goodwill.
🎧 Agent
Subscription Type = In-app
Subscription managed by Apple/Google — we can't cancel or refund directly. Provide instructions for cancelling via App Store or Play Store. If they already cancelled via app store, verify in our system that entitlement is removed.
🎧 Agent

Resolution — Closing the Ticket
Before clicking Send & Close, the agent completes the final fields. The Resolution field is the foundation of all reporting — fill it carefully.
Resolved — Answered
Agent answered a question or explained something. No action was taken in the system.
Resolved — Action Taken
Agent performed an action: cancelled subscription, reset account, applied credit, changed email, etc.
Refunded (Full)
Full refund processed. Note amount in ticket for finance audit trail.
Refunded (Partial)
Partial refund processed. Note amount and reason for partial in ticket.
Credit Added
Account credit applied as alternative to refund. Log amount.
Escalated — Pending
Ticket cannot be closed — awaiting another team. Keep Pending until resolved externally.
Resolved — Platform Fix
Issue resolved by production/platform team upstream. Agent informed customer.
No Response — Closed
Customer did not reply after 5 days. Set by automation or manually by agent.
Duplicate Contact
Customer sent the same issue multiple times. Close this ticket; link to the primary ticket.
🚫
Resolution = Escalated — Pending means do NOT close. Keep the ticket in Pending state until the external team (rights, production, finance, security) has resolved the issue. Only then update Resolution and close.

Tag Governance
Because Beacon enforces the Anchor Tags on intake, stray tags typed manually by agents stand out immediately. Monthly review keeps the tag set clean.
The 22 approved tags — reference list
Symptom Tags (17)
black screen — No picture, video area is black
no audio — Video plays, no sound
buffering — Loading spinner, stops/starts
quality issue — Pixelated or low resolution
casting issue — Cannot cast to TV/device
venue signal — Production-side broadcast problem
geo blocked — Geographic rights restriction
vpn detected — VPN detected by platform
wrong territory — Content not in their region
duplicate charge — Charged more than once
3d secure — 3D Secure / SCA failed
card declined — Bank declined the card
replay missing — VOD not available post-event
wrong content — Wrong stream/language/match
event canceled — Event did not take place
password reset — Reset needed or not arriving
account locked — Account suspended/locked
Operational Flag Tags (5)
known incident — Multiple reports, same issue, same time. Batch-hold all.
live urgent — Live event affected right now. Immediate escalation required.
proactive followup — Agent must follow up — do not auto-close.
vip — VIP customer or partner — prioritise and notify manager.
fraud — Suspected fraud. Separate workflow. Do not reply to customer.
Anchor Tags (Beacon-Applied)
cancellation request · refund request · payment failed
duplicate charge · billing question · streaming issue
black screen · audio issue · geo blocked · password reset
login failed · email change · app issue · casting issue
general feedback · schedule question · subscription question
Applied automatically by Beacon — agents do not need to add these manually.
📋
Monthly tag pruning process: Help Scout → Reports → Tags. Sort by volume. Any tag not in the approved list above = stray tag. Bulk-delete via migration CSV (contact HS support) or address individually. If a stray tag appears frequently, it may indicate a genuine gap in the Beacon form — consider adding it as a new option.
